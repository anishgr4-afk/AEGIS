## What was built

### Environment

- Python venv at `.venv/` with Flask, pytest, pypdf, pdfplumber, pypdfium2.

### Wearable simulation: `simulator.py`, `telemetry.py`
- `simulator.py` streams to `POST /api/telemetry`. It simulates:
  - **Garmin watch**: about 14× fewer readings than the Astroskin, plus
    motion spikes, falsely low SpO₂ and loose-strap gaps.
  - **Astroskin shirt**: worn during exercise, the first 10 minutes, and any
    non-nominal scenario.
  - **Glucose patch**: one reading every 5 minutes.
  - The vitals follow the console's clinical scenario, drifting towards it
    over a few minutes.
- `telemetry.py` (a Flask blueprint) does triage on a rolling median, and:
  - prefers the Astroskin when it's worn;
  - pauses rate rules during exercise and recovery;
  - reports a missing signal as "not measured", not as normal;
  - needs at least 5 readings before judging;
  - lets wrist SpO₂ alone raise "watch" but never "act".
- Results: across 40 simulated two-hour runs, zero false "act" alerts.
  Fever was detected in 20 of 20 runs, even with only the watch.

### Emergency checklist lookup: `checklist.py`, `scripts/split_checklist.py`
- `data/checklist_sections.json` is a hand-built index of 68 procedures from
  `Medical Checklist Rev H.pdf`, using printed page ranges.
- `scripts/split_checklist.py` writes one PDF per procedure to
  `data/checklist/`, plus `manifest.json`. Each PDF gets:
  - a blue "start here" marker;
  - an orange highlight on each `*` medication (surgeon approval first) -
    153 marks in total;
  - a "simulated demo" banner.

  The script fails if a procedure's heading isn't on its start page, which
  is how the page ranges are verified.
- `data/checklist_triage.json` is the decision tree: 46 rules and 19
  crewmate-observed signs, using the 12 `clinical.py` symptoms unchanged.
  Every rule cites a checklist page. **It is a draft, awaiting team review.**
- Endpoints:
  - `POST /api/checklist/match` uses live wearable vitals automatically.
  - `GET /api/checklist/pdf/<id>`
  - `GET /api/checklist/sections`
  - `GET /api/checklist/inputs`
- Match results list any inputs no procedure covers, and attach the current
  comms delay to "Contact Surgeon" steps.

## Gotchas discovered

- **Text extraction from the checklist PDF is garbled.** Capital "I" comes
  out as `(cid:1)`, and dashes as U+FFFD. Normalise them (see
  `GLYPH_FIXES`), or show the rendered pages instead.
- **`data/medical_database.json` isn't usable for lookup.** It's a
  teammate's auto-extracted index of 197 entries, many of them fragments
  ("Warning", "Note", "Met"), all with empty steps and no page numbers. The
  checklist feature doesn't use it.
- **Checklist PDF pages 1–16 are front matter and tables of contents.**
  Their dotted leader lines create false page-label matches.
- **Asterisks mean two different things in the checklist.** `*DrugName`
  means surgeon approval is needed. A bare `*` is the border of a boxed
  note. The border asterisks sit off the text baseline, so match them by
  nearby height, not by line.
- **Wearables give skin temperature, not core temperature.** Never apply
  the 38 °C fever rule to them. The checklist lookup only counts a fever
  from a thermometer reading.
- **Sparse watch signals reach back into workouts.** One breathing-rate
  reading a minute means a 5-reading window spans 5 minutes, so the rules
  stay paused until the window holds only rested readings. A clock-only
  recovery timer caused false alarms.
- **Flask runs with `debug=False`.** Code changes need a restart, and a
  restart empties the in-memory wearable buffer, including recent exercise
  context.
- **`/api/clinical/vitals` writes the audit log and a file on every call.**
  Never point a high-rate feed at it; use `/api/telemetry`.
- **Windows console and Python.** Printing "SpO₂" from Python in PowerShell
  fails with a cp1252 error, so write files with `encoding="utf-8"` instead.
  Large Bash heredocs containing quotes sometimes failed to parse; the Write
  tool is more reliable.
- **A teammate committed `__pycache__/*.pyc`** even though `.gitignore`
  lists `__pycache__`, so it shows as modified after any run.
- **Only the Fraunces weights actually used are embedded** (400 and 500).
  Styling something at 600+ silently falls back to a system serif. Check
  with: every `var(--f-disp)` rule should set a weight that is embedded.
- **v7 is a fork, not a theme.** It carries the same 13 guides and nearly the
  same script, so copying its stylesheet across is safe, but copying its
  script would have reverted this session's fixes.
- **`mix-blend-mode:screen` is what makes the checklist figures work.** The
  scanned line art has a white background; screen blending drops it. Keep
  the frame behind them near-black (`#050408`) or they turn into grey boxes.
- **No browser tool in this session.** The page was verified by running its
  script against a stub DOM (`harness.js` pattern: fake `document`,
  `getElementById` returning stub elements, real `fetch` pointed at
  127.0.0.1:5000) and asserting on the HTML it produced.
- **The two comms delays disagree.** `src/` (`EarthLink.tsx`) hardcodes
  12 min one way / 24 min round trip; the mission data says 1120 s one way
  (~37 min round trip). The team needs to pick one.

### Same day, later: live telemetry for the whole crew

- **Every crewmember is live.** `data/crew.json` holds the roster, and
  `telemetry.py` keeps one store per person, so one person's readings never
  affect another's triage. Readings carry `crew`; those without it go to the
  default wearer (MS2), so older callers still work.
- **Simulator scenarios are per person.** The default is MS2 in
  `hypovolemic_shock` and the rest nominal. Change it with
  `--crew PLT=post_eva_dcs,...`, and `--follow-console` brings back the old
  console-following behaviour. Exercise slots are staggered between crew.
- **Lifeline page:**
  - the hardcoded sample vitals are gone;
  - the page opens on the most urgent crewmember;
  - the Earth-link delay moved under the link panel;
  - procedures are numbered in engine order, top 3 plus "Show more";
  - when the crew has entered inputs, the cards show only the matched
    procedures (this fixes irrelevant cards like Obstructed Airway for a
    head scrape);
  - filter chips are no longer disabled by the page's own tag filter.
- **Tests:** 150 passing (new: `tests/test_crew_telemetry.py`).
